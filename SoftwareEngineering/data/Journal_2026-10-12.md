Thariq Shihipar, an engineer at Anthropic, has been saying that
[HTML is superior to Markdown](https://www.lennysnewsletter.com/p/html-is-the-new-markdown-how-anthropic)
for producing documentation.  Well, duh!  HTML **is** more expressive than
Markdown.  But it's also much more tedious to write.  That's the whole reason
for Markdown.  A lot of text can benefit from a tiny subset of HTML: paragraphs,
headings, lists, links, bold, italic, and code.  You get 90% of the benefits for
10% of the effort.  If a human is producing the text, Markdown is the way to go.

Thariq talks about artifacts generated by AI, like specs and implementation
plans.  If a machine is producing the text, it may be worth the effort to
generate full-styled HTML.  In the case of AI-generated text, though, HTML
probably uses more output tokens than Markdown.

He mentions including images in HTML specs.  Markdown and HTML both render
images stored in separate files, that need to be generated at the same time.
Either the AI returns a MIME multipart response or a single archive file.  It
might be able to inline SVG images in the HTML, but you could inline it just as
well in Markdown.

In the end, you can get more stylized documents with HTML, at the cost of extra
output tokens.

For text that **I** write myself, I'm going to stick with Markdown.
